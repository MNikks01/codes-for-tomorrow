# Trade-offs

Decisions that shape this codebase, what each one costs, and when to revisit it.

| #   | Decision                                                                                                                                                                                                                                          | Why                                                                                                                                                                                                                                          | Cost / when to revisit                                                                                                                                                                                               |
| --- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 1   | **Modular monolith**                                                                                                                                                                                                                              | Small domain, one deploy, no network hops between modules.                                                                                                                                                                                   | Modules scale together. Extract one only if it needs independent scaling.                                                                                                                                            |
| 2   | **PostgreSQL owns users, chats and membership. Firestore owns messages, receipts and last-seen.**                                                                                                                                                 | Membership is the security boundary and needs FKs, UNIQUE and transactions. Messages are append-heavy and naturally partitioned per chat.                                                                                                    | Two databases to operate. Every chat request does one cheap PostgreSQL membership lookup before Firestore.                                                                                                           |
| 3   | **No distributed transaction and no outbox.** The Firestore message write is the commit point. The PostgreSQL `last_activity_at` update afterwards is monotonic (`WHERE last_message_at < $new`), retried once, and re-run by idempotent retries. | An outbox only closes the gap if it lives on the Firestore side with a relay worker. That is a lot of machinery to protect one derived sort key.                                                                                             | If the update fails twice, chat-list ordering lags until the next message (logged as `chat_activity_sync_failed`). Messages are never lost. Add a Firestore-triggered relay once more PostgreSQL side effects exist. |
| 4   | **Canonical `direct_key = min(a,b):max(a,b)` with a UNIQUE constraint** for one-to-one chats                                                                                                                                                      | The database enforces it under any concurrency. No locks or retries. `chat_members` stays uniform for future group chats.                                                                                                                    | One extra column. The format is enforced in code (`directChatKey`), not by a regex CHECK.                                                                                                                            |
| 5   | **Idempotency via deterministic Firestore doc id** `sha256(senderId, Idempotency-Key)` plus `create()`                                                                                                                                            | Atomic deduplication with no idempotency table or TTL cleanup.                                                                                                                                                                               | A key can't be reused for different content (`409`). Without a key, a retried send can duplicate.                                                                                                                    |
| 6   | **Message pages are newest-first; each page is chronological.** The cursor is `(seconds, nanos, docId)`.                                                                                                                                          | Chat UIs open at the latest messages. Nanosecond precision plus a doc-id tie-break gives a total, stable order with no gaps.                                                                                                                 | Clients page backwards. Forward paging from the start is not offered.                                                                                                                                                |
| 7   | **Chat list is keyset-paginated on mutable `last_activity_at`**                                                                                                                                                                                   | "Most recent first" is the required order, and keyset pagination is O(page).                                                                                                                                                                 | A chat that gets a message while a client is paging can jump to page 1 and be missed on later pages. Normal for chat lists.                                                                                          |
| 8   | **Identity comes only from the JWT.** `senderId`/`userId` stay in the contract as optional fields and must match the token.                                                                                                                       | Prevents impersonation while keeping the assignment's request shapes.                                                                                                                                                                        | Small deviation from the original contract (documented in the README).                                                                                                                                               |
| 9   | **HS256 access tokens (15 min) plus opaque, single-use, hashed refresh tokens.** Reuse revokes the family.                                                                                                                                        | Stateless request auth. Theft is detectable. Rotation and successor insert happen in one transaction.                                                                                                                                        | An access token can't be revoked before it expires (≤ 15 min). Switch to RS256/JWKS if other services must verify tokens.                                                                                            |
| 10  | **In-memory rate limiting**: per IP, plus per account on login                                                                                                                                                                                    | No extra infrastructure for a single instance.                                                                                                                                                                                               | Limits are per replica. Use a Redis store when running more than one instance.                                                                                                                                       |
| 11  | **Refresh token returned in the JSON body**                                                                                                                                                                                                       | Simple for API and mobile clients.                                                                                                                                                                                                           | Browsers should keep it in an `HttpOnly` cookie behind a BFF.                                                                                                                                                        |
| 12  | **Unversioned alias of `/api/v1`**                                                                                                                                                                                                                | The assignment's literal paths (`POST /chat/create`) keep working.                                                                                                                                                                           | Two URLs per route. Future versions mount only under `/api/vN`.                                                                                                                                                      |
| 13  | **Firestore rules deny all; only the Admin SDK has access**                                                                                                                                                                                       | One enforcement point: backend membership checks.                                                                                                                                                                                            | No direct client listeners. Real-time needs a gateway or custom tokens with member-scoped rules.                                                                                                                     |
| 14  | **TypeScript 6, not 7**                                                                                                                                                                                                                           | typescript-eslint supports `< 6.1`.                                                                                                                                                                                                          | Slower compiler. Upgrade when the lint toolchain supports 7.                                                                                                                                                         |
| 15  | **Dependency versions held behind pnpm's release-age cooldown; build scripts allow-listed**                                                                                                                                                       | Lowers the risk of pulling a freshly compromised release.                                                                                                                                                                                    | Lags the newest patch by a day or so.                                                                                                                                                                                |
| 16  | **Runtime image deletes the Prisma CLI that pnpm keeps as an optional peer of `@prisma/client`**                                                                                                                                                  | Image shrinks from 925 MB to 625 MB. Migrations run from a separate `migrate` image.                                                                                                                                                         | A targeted `rm` in the Dockerfile. Revisit when pnpm can drop resolved optional peers in `--prod` installs.                                                                                                          |
| 17  | **Groups have one OWNER plus MEMBERs (no admins).** The owner renames and adds or removes members; anyone can leave.                                                                                                                              | Covers group management with one rule set. A partial unique index enforces a single owner, and membership changes take a `SELECT … FOR UPDATE` lock on the chat row, so the size cap and ownership hand-over stay correct under concurrency. | No delegated moderation. A departing owner's successor is chosen automatically (earliest joiner, then user id).                                                                                                      |
| 18  | **Last member leaving deletes the group in PostgreSQL**                                                                                                                                                                                           | No orphaned empty groups in chat lists.                                                                                                                                                                                                      | Its Firestore messages remain but become unreachable, because no membership can exist. Add a cleanup trigger if storage matters.                                                                                     |
| 19  | **Message delete is a soft delete (tombstone)**: text erased, `deletedAt` set, the entry stays in history with `text: null`. Only the sender can edit or delete.                                                                                  | Pagination cursors, read receipts and last-seen pointers that reference the message stay valid, and clients can render "message deleted". Edit and delete run in a Firestore transaction, so a racing edit can't resurrect deleted text.     | Deleted messages still count towards page size. There's no group-owner moderation of others' messages and no edit history.                                                                                           |
